# Claude notes

The rules in AGENTS.md apply. This file only adds what an agent needs to know quickly and what the code doesn't show.

## Map

- `engine/`: portable C++20 (matches KiCad 10). `c_api.h` is the only surface Swift sees. It uses C structs with fixed `char[]` fields, opaque `cc_board*`/`cc_schematic*` handles, and `(char* error, size_t capacity)` out-buffers. The Swift side passes a 512-byte buffer. Authoring calls return a new full file text (`char*`, freed with `cc_free_text`) and never write the file themselves.
- `app/Sources/`: the SwiftUI iPad app, iOS 17 minimum (`app/project.yml`, iPad only). The Xcode project is generated by XcodeGen and is not committed.
  - `ContentView.swift`: the `Design` (board) model, the SceneKit enclosure preview, the root layout, project create/open, and the sidecar `enclosure.corvcad.json`.
  - `SchematicDesign.swift`: the `SchematicDesign` model and the `schematicText` C-string helper.
  - `SchematicOverview.swift` / `PCBOverview.swift`: `Canvas`-drawn editors (tool picker, snapping, hit testing).
  - `TouchCanvasControls.swift`: a UIKit touch surface for tap, hold (0.42 s), drag after the hold, and live finger preview, plus `OrbitMenu`, the hold menu.
  - `Theme.swift`: the design system (tokens, components, canvas reticle and halo). `HomeView.swift`: the project home and the new-project sheet. `WorkspaceView.swift`: the workspace shell, mode switcher and inspectors.
- Board edits: the C API returns new text, Swift writes it atomically to the project file, then reloads and reparses. Schematic edits on local projects go through the engine's `SchematicSession` (`schematic_session_c_api.h`): one transaction per touch action, saved right away, with hierarchy and its own history. `EditHistory` in `ContentView.swift` orders board file steps and schematic session steps into one undo stack. The session is a compatibility backend, not KiCad; see `docs/KICAD_CORE_PORT.md`.
- Imported (non-project) files are read-only for touch edits. Their legacy move and property edits save copies to the temp directory.

## Environment

- The usual dev box is Windows without Xcode, Swift, CMake or KiCad. Build and test on the Mac over SSH instead: host alias `corvmac` in `~/.ssh/config` (key `~/.ssh/corvcad_mac`). It is an Intel iMac on macOS 26 with Xcode 26.2, the iOS 26.2 simulator, CMake, Ninja and XcodeGen, and it has no GUI session. Sync the working tree with `tar` over SSH to `~/corvcad` (exclude `.git`, `build`, `.claude`, `app/CorvCAD.xcodeproj`). Then run the engine `cmake`/`ctest` and `xcodegen` + `xcodebuild` there. Xcode 27 / the iOS 27 SDK needs Apple silicon, so release builds need an Apple-silicon Mac. The repo has no Codemagic or CircleCI config any more; the ones used until 2026-11-12 are in commit `ef8ae6c` for reference.
- Simulators on the Mac: `CorvCAD iPad mini`, `CorvCAD iPad Pro 11`, `CorvCAD iPad Pro 13` (iOS 26.2 only). The Simulator app can't be driven without a GUI session, so the `CorvCADUITests` target is the way to rotate the device, tap and screenshot. `ScreenshotTests` captures every screen in portrait and landscape. Pass `TEST_RUNNER_SNAPSHOT_DIR` to write PNGs. Debug builds also accept the launch environment `CORVCAD_OPEN=<project>`, `CORVCAD_MODE=schematic|pcb|enclosure` and `CORVCAD_SHEET=<sheet uuid>`. Review every UI change in both orientations.
- On this box `python` is the Microsoft Store stub. Run scripts with `py -3` (for example `py -3 tools/board.py me`).
- Don't add Swift packages or new targets without updating `app/project.yml`, the CI workflow and `THIRD_PARTY.md` together.

## UI work

- Before writing SwiftUI, use the `swiftui-expert` skill. Target iOS 17 APIs and gate anything newer with `#available`.
- The engine stays UI-free. Visual and design-system code lives only in `app/`.
- Design language (the Corvusar brand, modelled on gravore.com): dark only, with a void-black background and white structural lines. **Gold** (`Corv.gold`) marks action, selection and the current tool. **Cyan** (`Corv.cyan`) marks live data: snapping, coordinates, counts, B.Cu. Destructive actions use `Corv.red`. Technical labels use `MonoLabel` (monospaced, uppercase, tracked). Use system fonts only. Chrome floats over full-bleed canvases (`corvPanel`). Don't use raw system colors or stock `Form` sidebars. Respect Reduce Motion for decorative animation.
- The brand logo is not in the app yet. Don't add it until asked.
- On-screen claims must stay as precise as the README. Don't present STEP outside the `NATIVE_FREECAD` edition (where Fabricate exports FreeCAD's exact solids since the 2026-10-31 STEP gate), autorouting, live clearance checks, or automatic schematic↔PCB sync as available. Manual tracks and vias, the Draw tool (zones, outline replacement, silkscreen/fab lines and text, which hold menus move, edit (text) and delete; zones stay unfilled in the default edition, KiCad fills them in `NATIVE_KICAD`) project libraries (import, create, remove; symbol and footprint editing on a canvas; one undo step per change; both editions, but only `NATIVE_KICAD` places their parts), the Gerber viewer and the PCB calculator (both editions), the Fabricate tab (specs, a material estimate, and the edition's outputs; drawings and a slicer hand-off are roadmap items with no placeholder there), the FreeCAD edition's enclosure timeline, connector wall cutouts, vent slot rows, lid screws, sketch mode (rectangles, circles, polygons with arc edges; cut or extrude) and mechanical-only projects (no KiCad files; FreeCAD edition only), the 3D view's generated board parts (chip R/C, THT pin headers, gull-wing packages from KiCad's generator; FreeCAD edition only, placeholders elsewhere) with their clearance checks and the on-request **Update from schematic** (pad nets) do exist. KiCad's board edits (flip a footprint, a track's width and layer, aligned dimensions, a copper zone's properties, placing a library footprint and Change Footprint; `cc_board_native_edit`), KiCad's own DRC, zone refill and Update PCB from Schematic (board inspector and the PCB view's update button), KiCad's importers for other CAD projects (Altium, Eagle, EasyEDA, EasyEDA Pro, CADSTAR, PADS, P-CAD, Fabmaster, LTspice, gEDA; Home's "Altium, Eagle…" into a new project; cc_board_native_import, session API 10 cc_sch_import), placing any official KiCad library symbol with the footprint chooser, and the Track tool's interactive routing with KiCad's router (walk around, shove, highlight collisions, vias, differential pairs, length and skew tuning, dragging tracks and vias; not an autorouter), fabrication outputs (Gerbers with job file, Excellon drill, placement CSV) and PDF/SVG plot, Board Setup (copper layers, the stack-up's dielectric layers, design rules, netclasses), the schematic tools of session API 6, 8 and 9 (annotate, buses and wire or bus entries, global/hierarchical labels, new, resized and deleted hierarchical sheets and sheet pins, power rails, BOM, no-connect flags, symbol mirror, text notes and note lines; `CC_SCH_KICAD_TOOLS`), KiCad's ERC, netlist export and schematic PDF/SVG plot in the schematic inspector (`CC_SCH_ERC`, `CC_SCH_NETLIST`, `CC_SCH_PLOT`), and KiCad's simulator (`CC_SCH_SIMULATE`: the schematic inspector's Simulation section, the plot over the canvas, and the Electrify bar in the 3D view, where only voltages come from the simulator and current in the copper is calculated) exist only in the `NATIVE_KICAD` edition, gated on `cc_board_native_backend()` or the capability bit; the default edition has none of them and must not show them.
