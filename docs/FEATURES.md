# Feature reference

Everything CorvCAD does today, screen by screen, with the edition each feature needs and the checks behind it. The [README](../README.md) has the overview.

## Projects, schematic, PCB and enclosure

1. Create a local KiCad project with **New project** on the home screen. Enter a name and starter board width/height; CorvCAD creates matching `.kicad_pro`, `.kicad_sch`, and `.kicad_pcb` files with a rectangular `Edge.Cuts` outline. Reopen it from its card under **Local projects**. The folder is visible in Files under **On My iPad → CorvCAD → Projects**. CorvCAD saves enclosure controls in `enclosure.corvcad.json` beside the KiCad files. Existing names are never overwritten.
2. In the **Schematic** workspace, choose **Part**, **Wire**, or **Label** from the floating tool rail. Wires snap to nearby pin ends and wire endpoints and route at right angles around part bodies and connection points; overlapping part placement is rejected. Hold a symbol, wire, or label for an orbit menu of direct actions; keep the finger down and release over an action, or lift and tap one. In **PCB**, choose **Part** or **M3**; hold a footprint for Move, Rename, or Delete. Numeric moves and property edits live in the inspector (top-right button). These actions save the project's KiCad files and preserve unrelated expressions. Project-local `CorvCAD.kicad_sym` and `CorvCAD.pretty` libraries travel with the folder. See [touch editing](TOUCH_EDITING.md) for exact steps and limits.
3. Import a KiCad `.kicad_pcb` file. The engine reads the `Edge.Cuts` outline (`gr_line`, `gr_arc`, `gr_rect`, `gr_poly`), footprint references/values/positions, mounting-hole drills, plus nets, tracks, vias and pads.
4. Inspect copper layers and nets in a native 2D PCB overview. Move a footprint within a local project or save an edited copy of an individually imported board; this preserves unrelated source text but does not reroute copper. The one-sheet schematic overview draws CorvCAD two-pin symbols and their pin ends; other symbols are drawn from the sheet's embedded library graphics (body, pin lines, pin names and numbers), and wires snap to their pins. Symbol moves and Value and Footprint edits preserve unrelated source text. With **Select**, tapping a wire, label or pin end highlights its net, using the engine's portable connectivity for one sheet. That connectivity matches KiCad 10's netlist, names included, on all 25 single-sheet KiCad demo projects. It does not model buses or connections across sheets.
5. Adjust margin, wall and floor thickness, board clearance, standoff height, boss diameter, lid thickness and lid gap.
6. Preview separate floor, walls, rim, board, bosses and lid in a native, orbitable iPad 3D view using SwiftUI and Metal-backed SceneKit. The lid can be hidden or shown in an exploded view so assembly seams are visible. **Parts** shows the board's components where a footprint names a 3D model: in the FreeCAD edition, chip resistors and capacitors, 2.54 mm through-hole pin headers and gull-wing SOIC, SSOP, TSSOP, QFP and SOT packages are generated from their KiCad model names by a C++ port of KiCad's own 3D model generator (1,058 names; no 3D model files are bundled). Other models, and every model in the other editions, appear as marked translucent placeholders over their pads.
7. Export separate ASCII STL files for the tray and lid. A desktop engine built with Open CASCADE can also export the tray as STEP.

In the default edition the tray is rectangular around the board bounding box. The lid is a plain plate with an adjustable clearance. The current bosses are solid, so the exported STLs are **fit and layout prototypes**, not validated printable fastening designs. That mesh model does not account for component heights, connector openings, draft, detailed tolerances, inserts, lid fastening, board mounting screws, or slicer settings. Inspect the output before manufacturing. Files with multiple/disconnected `Edge.Cuts` loops are rejected; a simple outer loop is required.

The portable readers and iPad overviews are **not KiCad's editing engine**. Touch authoring currently covers a small two-pin part, wires, labels, a matching PCB footprint, and a mounting hole. Hold menus move, rotate (90° steps), rename and delete items. They also edit a symbol's Value and Footprint. A wire that ends on another wire writes the junction KiCad requires. Two fingers pan and pinch-zoom both canvases, and undo also covers the enclosure parameters. **Update from schematic** in PCB mode copies a single-sheet schematic's nets onto the pads of matching footprints and adds missing two-pad footprints. After it, KiCad 10's audit and schematic-parity DRC find the touch-authored round-trip project consistent. **Track** and **Via** draw F.Cu/B.Cu copper by hand: a track starts on a pad, track end or via and takes its net. A touch-routed round-trip board passes KiCad 10.0.6 DRC with schematic parity: zero violations and zero unconnected items. **Draw** adds a copper zone on F.Cu or B.Cu, with a net and KiCad's default zone settings. It can also replace the board outline with a polygon, and add lines and text on the silkscreen and fab layers. Hold a zone, line or text to delete it. The default edition writes zones unfilled, so run KiCad's zone refill on them. The sideloaded edition below fills them with KiCad's zone filler. For a board drawn with these calls, KiCad's DRC, zone fill and Gerbers matched `kicad-cli` 10.0.6's in the desktop check. It does not export a netlist, sync automatically, swap footprints, autoroute, check clearances while drawing, or perform on-device ERC/DRC. Touch additions and direct edits save local project files; moves on individually imported files save separate copies. Run KiCad DRC/ERC after edits. For KiCad-backed DRC/ERC, Gerbers, drills, position files, board STEP, schematic netlist/BOM/PDF export on desktop (the default iPad edition has none of these; the sideloaded edition below has some), use [the KiCad CLI bridge](KICAD_INTEGRATION.md). An additional [KiCad-native desktop PCB adapter](../integrations/kicad_native/bridge.py) runs KiCad's own model via its bundled Python bindings; it is a reference for the [headless source-port investigation](KICAD_CORE_PORT.md), not an iPad port. The included board fixture uses KiCad 10's named-net format and passes KiCad 10.0.6 DRC with zero violations and zero unconnected items. The blank starter project fixture passes KiCad 10.0.6 DRC and ERC with zero violations; a project containing an incompletely wired part will correctly report ERC violations. A project built entirely by touch in the simulator (parts, a detoured wire, a tee junction, labels, footprints, M3 holes) passes KiCad 10.0.6 ERC and DRC with zero violations, has exactly the intended nets and survives a KiCad re-save unchanged; see [the round trip](KICAD_TEST_PROJECT.md#touch-authored-round-trip-the-other-direction).

## Home tools

The home screen has a **Gerber viewer** and a **PCB calculator**, in both editions:
- The viewer reads RS-274X/X2 Gerber and Excellon drill files from Files, or the KiCad edition's fabrication export. Apertures and aperture macros, arcs, regions, polarity and slots are supported. Layers stack by their X2 function with their own colours. On KiCad 10.0.6's Gerbers of CorvCAD's fixture boards, it matched the boards: the outline's extents, a copper flash per pad, and a drill hit per hole. KiCad's own Gerber test files all read, and the deprecated commands it doesn't apply are named on screen.
- The calculator uses the formulas and constants of KiCad 10's pcb_calculator: IPC-2221 track width and current, via resistance and ampacity, IPC-2221 electrical clearance, adjustable-regulator dividers, and E-series values with the resistor colour code.

## Project parts

**New projects** choose their parts: Electronics (it can be turned off for a mechanical-only project in the FreeCAD edition) and an Enclosure. An electronics-only project has no Enclosure tab and starts no FreeCAD; Fabricate adds the enclosure later. The choice is kept in the project's `corvcad.project.json`; projects without it have an enclosure.

## FreeCAD edition enclosure

In the FreeCAD edition the Enclosure inspector is a **timeline** of the FreeCAD document's own PartDesign features (body, cavity, standoffs, bores, lid), each with the parameters that drive it. **Connector cutouts** are suggested for connector footprints (J, P, CN, USB, X) whose pads come within 6 mm of a board edge: a toggle adds a box through that wall, sized from the pads and adjustable in width, bottom and height, as one undoable step saved in the `.FCStd`. **Vents** add rows of slots through the lid or a side wall (a slot and a FreeCAD linear pattern, with slot count, size and pitch), kept off the edges, the corners and other openings. **Lid screws** (M2, M2.5 or M3) add square posts in the cavity's corners with pilot holes for self-tapping screws or holes for heat-set inserts, and clearance holes through the lid; turning them on raises the board margin to fit the posts in the same undo step. **Component clearance** checks the generated parts' heights (see Parts above) against the top clearance and the standoff height, and offers to raise a parameter that's too small; connector cutouts take their height from a generated connector body. **Sketch mode** draws rectangles, circles and polygons on the lid's top or a wall's outer face (0.5 mm grid, horizontal and vertical edges inferred and marked, dimensions typed in, a polygon edge's length solved by FreeCAD's Sketcher, any edge bent into an arc of up to a half circle by dragging its handle), then cuts them in (through or to a depth) or extrudes them out; each sketch is a fully constrained FreeCAD Sketcher sketch and a Pad or Pocket. Sketch shapes may not touch each other or the face's other openings, checked exactly by FreeCAD (a shape may sit inside another's notch). **Mechanical-only projects** (FreeCAD edition): turning Electronics off in New project makes a project with no KiCad files, an enclosure around a typed inside width, depth and height, opened in Enclosure and Fabricate; it has no standoffs or connector cutouts. The session checks every recompute against the exact expected tray and lid volumes and bounds. The default edition keeps its parameter panels and has no cutouts, vents, lid screws or sketches.

## Fabricate

The **Fabricate** tab, after Enclosure, gathers what will be made and every output the edition can write:
- Board specs: size, thickness, copper layers, counts and via drills. The KiCad edition adds the Default netclass rules, unrouted connections and DRC/ERC status.
- Enclosure specs: tray and lid sizes and volume, measured from the exported STL meshes, with a mass and filament estimate for a chosen material (solid parts; a slicer's settings change both).
- Outputs: the KiCad project as a zip, tray and lid STL, and one OBJ with both parts, in both editions. The KiCad edition adds the fabrication package, board and schematic PDF/SVG, BOM and netlist; the FreeCAD edition adds exact **STEP** of the tray and lid and the `.FCStd` document. Technical drawings and a slicer hand-off are on the roadmap, not in the app.

## Project libraries

**Project libraries** in the schematic inspector list the project's symbol and footprint libraries. They import a `.kicad_sym` file, a `.pretty` folder or one `.kicad_mod` file from Files, and they create or remove libraries. They also edit symbols and footprints on a canvas:
- pins or pads, rectangles, lines and circles, and moving or deleting them
- pin and pad properties, symbol fields and units
- the fields of a derived symbol
- templates for a box symbol or rows of pads

An edit changes only what it touches in the KiCad text, so other shapes, text, properties and pad settings are kept. Each library change is one step of the workspace's undo. In the default edition these libraries are files for KiCad: the Part tool still places CorvCAD's two-pin part.

## Schematic session and the KiCad edition

For the schematic source-port work, the portable engine now also has a project-level, transactional **compatibility** session with hierarchical sheet discovery, undo/redo, source-preserving edits, and save-copy. The iPad app opens local projects' schematics through its [versioned C ABI](SCHEMATIC_SESSION_API.md): child sheets appear as boxes you can open, and every touch edit is a transaction saved immediately. The backend identifies itself as `compatible-source-edit` and has no KiCad ERC, connectivity or netlist; the app says so in the schematic inspector. Inspect a project with `build/engine/corvcad_schematic_session_cli path/to/project.kicad_pro`. KiCad 10.0.6 source and the complete official symbol set are pinned and fetchable via `integrations/kicad_core/fetch.py`; the default build links no KiCad source or symbol bundle. An experimental sideloaded edition (`xcodebuild ... NATIVE_KICAD=YES`, GPL-3.0-or-later) replaces the compatibility session with KiCad 10.0.6's own schematic model and adds KiCad's board code: DRC and zone refill in the board inspector, Update PCB from Schematic, KiCad's importers for other CAD projects (Home's "Altium, Eagle…": Altium, Eagle, EasyEDA and EasyEDA Pro, CADSTAR, PADS, P-CAD, Fabmaster boards and LTspice and gEDA schematics into a new project, as KiCad's editors import them), KiCad's simulator (ngspice 46 with XSPICE, from the schematic inspector: transient, AC, DC sweep and operating point, a plot with probes on the schematic, and the result on the 3D board: nets glowing with their voltage, and calculated current along the tracks; no Verilog-A models; not validated on a device), the official symbol and footprint libraries and the project's own (a part picker and a footprint chooser; KiCad reloads the project's libraries after a library change), and interactive routing with KiCad's push-and-shove router in the Track tool (walk around, shove or highlight collisions, vias, differential pairs, length and skew tuning, dragging tracks and vias; not an autorouter). It also exports fabrication files with KiCad's own writers: Gerbers with the job file, Excellon drill files and a placement CSV, identical to `kicad-cli` 10.0.6's on six boards in the desktop check, plus PDF and SVG plots. It also has KiCad's board edits (flip a footprint, a track's width and layer, aligned dimensions, a copper zone's properties with a refill, placing any library footprint and KiCad's Change Footprint; `kicad-cli` reopens the results with the same DRC), KiCad's Board Setup (copper layers, the stack-up's dielectric layers, design rules, netclasses and their patterns) and KiCad's schematic tools: annotation, buses and bus entries, global and hierarchical labels, new hierarchical sheets with sheet pins (resized and deleted too), bus-to-bus entries, a power-rail menu, no-connect flags, symbol mirroring, text notes and note lines (netlist and ERC of the edited demos match `kicad-cli`, ERC's library checks set apart), and a BOM identical to `kicad-cli`'s on three demo projects, and a schematic PDF/SVG plot (all sheets, drawing sheet) whose pages and drawn elements matched `kicad-cli sch export pdf|svg` on the same three. These newer tools have been checked on the desktop build only, not on an iPad. It builds from local iOS dependency builds (or CircleCI) and has passed simulator UI tests. On a physical iPad Air (M2), with the bundled libraries, its netlists, ERC and KiCad board DRC matched `kicad-cli` on four KiCad demo projects. In the combined edition on the same iPad (2026-10-31), the BOM, the schematic PDF/SVG plot and the fabrication files also matched `kicad-cli` on the three demos with desktop references; the touch UI of these tools has been tested in the simulator only. It has no published release or corresponding-source archive yet. See [the source-port gates](KICAD_CORE_PORT.md).

## Input verification

The **Verify KiCad schematic inputs** GitHub Actions workflow verifies the [gate 1 source, patch and license inventory](../integrations/kicad_core/audit/README.md) when started by hand. All workflows here, Codemagic included, are manual-only; nothing runs on push. It also packs the complete official symbol set and publishes it as a short-lived artifact. The app build does not yet use that bundle. Native packaging work can use the [gate 1 handoff](history/KICAD_GATE1_HANDOFF.md).
